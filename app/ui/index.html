              Where it runs

              Life of a question

              Fixed code that behaves the same way every time A step where an AI model is involved

              1. Guardrails code

                Blocks prompt injection, requests for secrets and raw SQL before anything else runs.

                app/security/guardrails.py Open Privacy & security
              2. Answer cache code

                The demo's data never changes, so a question that was already answered is served at once and labelled "cached answer".

                app/agent/answer_cache.py
              3. Task router AI model

                Picks a pipeline (documents, accounting, drafting or general), which fixes the tools and the model tier the question gets. Keyword rules decide first; a fast model helps only when they are unsure.

                app/llm/intent.py
              4. Retrieval code

                Hybrid search: keyword (BM25) and vector scores are fused, then diversified. Only passages on the question's topic are sent ahead to the model.

                app/rag/retriever.py Open Documents
              5. Privacy router code

                Decides which data may go to a hosted model. Emails, phone numbers and account numbers are masked before anything leaves.

                app/llm/privacy.py Open Privacy & security
              6. Model router AI model

                Tries the models in order, skips one that keeps failing (circuit breaker), and waits once when every model is briefly rate limited.

                app/llm/router.py Open AI models
              7. Tools AI model

                The model can only call typed, validated tools: search the documents, run read-only SQL on DuckDB, and read the ranked attention list.

                app/agent/tools.py
              8. Checks code

                The answer is scrubbed for secrets, every [citation] is matched to a source that was actually retrieved, and unmatched ones are flagged.

                app/agent/engine.py
              9. Activity log code

                The question, route, model, sources and SQL are written to a hash-chained log, so any later edit is detectable.

                app/audit.py Open Activity log

              Around the chat

              Invoice reading
              Rules read the supplier, dates, totals and line items. Anything missing or inconsistent is flagged for a person to review. app/invoices/
              QuickBooks
              A read-only copy of the books, reconciled against the invoices and the bank statement. app/accounting/
              Reports and insights
              Month-end checklist, aging and a ranked "needs attention" list, all computed in SQL from the loaded data. app/accounting/reports.py
              Streaming
              Answers stream as they are written over server-sent events. Every chunk is scrubbed before it is shown. app/agent/streaming.py

              Full write-up with diagrams: docs/ARCHITECTURE.md in the source code.
